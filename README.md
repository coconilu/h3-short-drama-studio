# 镜场 · H3 短剧导演台

一个本地优先的短剧生产 MVP：在浏览器里维护剧本、镜头、参考素材与候选版本，通过受控适配层驱动本机 ComfyUI / MiniMax H3。

## 当前闭环

| 环节 | 当前实现 | 真实边界 |
|---|---|---|
| 剧本拆镜 | SQLite 中维护多个项目与镜头，可新建/切换项目、批量录入初始分镜，并编辑提示词、规格和策略 | 当前是本地单用户工作区；尚无项目归档、协作权限和云同步 |
| 素材管理 | 导入图片、视频、音频，复制到受管目录并记录媒体信息与 SHA-256 | 初始四项演示素材仍不可绑定；只有“受管文件”可进入 Ref2VA |
| 镜头引用 | 按图片/视频/音频分别绑定、设定用途和排序 | H3 上限为 9 图、3 视频、3 独立音频；参考视频须为 2–15 秒 |
| 生成计划 | 合并原始分镜、锁定生产圣经与真实引用，逐镜预览、H3 dry-run 并批准不可变快照 | 草稿圣经不生效；镜头或素材变化会让旧批准自动失效 |
| H3 校验 | 自动按最终引用顺序选择 FL2VA 或 Ref2VA，编译 `<Picture n>` 等标签后执行 `--dry-run` | 会构建真实节点图，不占用 GPU，也不会创建草稿任务 |
| 草稿生成 | dry-run 通过后，独立按钮二次确认并提交本机 ComfyUI | 是否使用 Ref2VA 由当前镜头的真实绑定决定 |
| 审片定稿 | 自动同步 manifest，播放真实候选、切换版本、备注并定稿 | EP01 的 7 个镜头均已有真实本地视频来源；01/02/04–07 为已选草稿，03 为 Ref2VA 定稿 |
| 成片时间线 | 版本化装配、逐镜字幕入点、导出门禁、冻结输入、持久化任务、成片播放、任务日志与历史版本回切 | 已实现可恢复的 FFmpeg 横屏导出；当前转场固定为硬切，未提供时间线混音编辑 |

## 架构

```text
React 导演台
  ├─ 剧本与分镜 / 资产 / 队列 / 审片 / 时间线
  └─ HTTP API
       └─ FastAPI + SQLite
            ├─ 安全确认门
            └─ h3-video-draft-refine 适配器
                  └─ ComfyUI :8188 → MiniMax H3 → 本地输出
```

## 启动

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1
```

前端默认运行于 `http://127.0.0.1:4173`，后端 API 默认运行于 `http://127.0.0.1:8765`。

`start.ps1` 会启动本地守护进程并等待 API 与网页都通过健康检查；API 或网页进程意外退出时会自动重启。运行状态与安全停止命令：

```powershell
.\scripts\status.ps1
.\scripts\stop.ps1
```

“系统设置 → 运行与恢复”会显示实际 PID、托管状态、日志位置与恢复次数。API 离线时，网页会保留已加载数据并自动重连；首次打开也会显示可操作的离线页，不再无限停留在加载动画。

只启动 API，或为验收指定隔离数据库与导出目录：

```powershell
.\scripts\start-api.ps1 -Port 8765
```

导出当前 7 镜头粗剪：

```powershell
.\scripts\export-roughcut.ps1
```

产物默认写入 `runtime\exports`。脚本会优先使用镜头定稿，其次使用已选草稿，并生成 MP4、可编辑 SRT 和来源追踪 JSON；任何镜头缺视频或音轨时会失败关闭。

平台提交导出时会冻结镜头来源、字幕设置和输入路径。工作进程认领后先把每个来源复制到本次 run 私有、只读且以 SHA-256 命名的 staging；复制前后会同时复核原文件和副本哈希，FFmpeg 此后只读取副本，不再依赖可能变化的原路径。最终发布在 Windows 上还会为全部 staged 输入持有 `CreateFileW(GENERIC_READ, FILE_SHARE_READ)` 句柄，禁止并发写入或删除直到 manifest/current 的事务 CAS 完成；无法获得等价 OS 保护的平台会失败关闭。生产清单同时记录 original/staged 输入与输出 SHA-256，可用以下命令回归任务状态机：

```powershell
.\.venv\Scripts\python.exe -m unittest backend.test_export_task_engine -v
```

## 安全边界

- “验证工作流”只调用 H3 脚本的 `--dry-run`，不会提交 GPU 任务。
- “提交生成”必须在界面中二次确认。
- 受管素材只允许从项目 `runtime/assets` 目录读取；界面演示图不能伪装为 Ref2VA 文件。
- 项目切换会同时隔离镜头、素材、引用、生成任务、审片版本与导出历史；直接访问其他项目的资源 ID 返回 404。
- MVP 的最终工作流仍由本地 `h3-video-draft-refine` 适配器负责，平台不复制 ComfyUI 节点图逻辑。

## P5 平台持久化导出闭环

“成片时间线”现在直接驱动持久化导出任务，而不是依赖终端手工运行脚本。

| 能力 | 行为 |
|---|---|
| 冻结输入 | 提交时保存 7 个已选镜头、对白和字幕时点，并记录快照 SHA-256 |
| 重启恢复 | 启动时识别遗留的“导出中/取消中”任务，重新排队或完成取消 |
| 取消 | 排队任务立即取消；运行任务终止进程树并清理同名未完成产物 |
| 重试 | 失败或取消后创建新尝试，保留父任务并沿用原输入快照 |
| 日志 | 数据库记录状态事件，FFmpeg 原始输出写入 `runtime\export-jobs` |
| 版本 | 每次成功导出自动成为当前版本，历史完成版本可人工回切 |
| 可追溯性 | 生产清单 schema v2 记录任务尝试、恢复次数、输入/输出哈希和媒体探测结果 |

当前任务执行器按单 API 进程设计；若未来需要多机或多个 API worker，应把认领与心跳迁移到独立队列服务。

## P7 整集批量生产安全门

分镜页可多选镜头并按 `ordinal` 顺序执行批量 dry-run；每个镜头都会独立返回 FL2VA/Ref2VA 路线和失败原因。只有全部所选镜头在最新配置下校验通过后，“提交所选生成”才会解锁。

| 门禁 | 行为 |
|---|---|
| 选择范围 | 可逐镜勾选，或一次选择全部未定稿且未处于生成中的镜头 |
| 批量 dry-run | 串行构建真实 H3 节点图并记录逐镜 validation 任务；`gpu_submitted: false` |
| 配置防漂移 | 镜头提示词或规格在校验后发生变更，服务端会拒绝批量 GPU 提交并要求重新 dry-run |
| GPU 确认 | 弹窗明确展示镜头数和候选总数；必须显式确认才按分镜顺序提交 |
| 关闭网页 | 已提交任务保留在 ComfyUI 和平台生成队列；尚未提交的选择不会后台偷偷启动 |

《电梯十三层》三镜头已完成批量 FL2VA dry-run（3/3 通过、共 6 条候选配置），只验证到 GPU 二次确认弹窗并选择“暂不提交”，实际草稿任务数为 0。

这套早期批量入口已由 P13–P14 的持久化生产调度器取代；旧 API 暂时保留用于兼容已有调用，不再作为页面默认提交路径。

## P8 剧本开发与本地 Agent

“剧本开发”页把创作层级建模为“整集 → 幕/章 → 场景/小节”，每一层都可以人工维护，也可以独立调用本机 Agent 生成修改提案。

| 层级 | Agent 能力 | 审核与落库 |
|---|---|---|
| 整集 | 重构全剧大纲、节奏和各幕分配 | 展示整集提案；人工接受后创建新版本 |
| 幕 / 章 | 重写当前幕的目标、冲突和场景顺序 | 只影响当前幕；人工接受后创建新版本 |
| 场景 / 小节 | 生成标题、剧情动作、对白、钩子、时长和张力 | 逐字段对比；可接受或拒绝 |

```text
创作者选择范围与要求
        ↓
本地 API 创建 Agent 任务
        ↓
Codex CLI 或 Kimi Code CLI（独立沙箱）
        ↓
结构化提案 → 页面差异审核
        ↓ 人工接受
新剧本版本（不直接覆盖既有分镜和生产任务）
```

安全边界：命令使用参数数组直接启动，不经过 shell；每个剧本同一时间只允许一个 Agent 任务；Agent 结果默认只读待审；已有生产镜头不会随剧本提案自动改写。实际生成前仍需要从已接受的剧本版本显式同步到分镜层。

当前已在本机真实验证 `codex-cli 0.147.0` 与 `kimi 0.35.0`，并分别完成一条场景提案；两条提案都保留在待审核状态，没有替用户接受。

## P9 锁定剧本同步到分镜

已接受的剧本不会直接改写生产镜头。同步使用“锁定版本 → 差异预览 → 明确确认 → 写入映射与记录”的安全门：

```text
剧本草稿 ──锁定──> 不可变版本快照
                         ↓
                  生成分镜同步预览
                         ↓
       新增 / 更新 / 不变 / 受保护 / 保留
                         ↓ 人工确认 + 版本哈希复核
                  写入分镜与同步记录
```

| 情况 | 当前处理 |
|---|---|
| 剧本新增场景 | 新建未生成分镜，并生成可继续编辑的初始 H3 提示词 |
| 已有场景改变 | 同步标题、剧情动作、对白、时长和排序 |
| 已有 H3 提示词 | 始终保留，不被叙事同步覆盖 |
| 镜头已有候选、成片或生成记录 | 标记为“受保护”并跳过剧情字段更新 |
| 场景从剧本中移除 | 原生产镜头保留，不自动删除 |
| 预览后数据发生变化 | 哈希校验拒绝旧预览，要求重新检查 |

每次执行会记录剧本版本、同步计划、执行前后 shots 快照和永久场景映射。当前未提供界面回滚按钮，但数据库已保留构建安全回滚所需的依据。

逐镜审核不是只显示“更新/不变”的结果标签。每个镜头都可以展开查看字段级处理：

| 审核列 | 含义 |
|---|---|
| 当前分镜 | 同步执行前的标题、画面描述、对白、时长和 H3 提示词 |
| 锁定剧本值 | 本次剧本版本建议写入的字段值 |
| 本次处理 | 明确标记“更新”“写入新镜头”“保留原值”或“跳过” |

已经执行过同步时，剧本页显示“查看上次同步差异”，打开的是持久化同步记录，不会再次修改分镜。旧记录也会根据保存的前后值自动补齐字段级审查信息。

## P10 本地服务可靠性

本机生产工作台改为“统一启动器 → API / 网页子进程”的守护结构：

| 故障场景 | 当前行为 |
|---|---|
| API 意外退出 | 守护器退避重启；网页显示断线横幅并自动重新同步工作区 |
| 网页首次打开但 API 离线 | 显示离线原因、数据安全说明、立即重连与启动命令，不再无限转圈 |
| 人工维护 | 系统设置显示 API、守护器、网页三层真实状态；托管状态下可受控重启 API |
| 重复启动 | 检测仍存活且状态新鲜的守护 PID，不再重复占用端口 |
| 安全停止 | `stop.ps1` 只向当前已验证的守护 PID 发停止命令，并由守护器结束其托管子进程树 |

真实故障演练已覆盖：直接结束 API 实际进程后自动恢复；从页面提交受控重启后 PID 更新；保持网页在线而关闭 API 时，冷启动离线页正确出现，恢复守护器后无需刷新即可回到项目面板。

## P11 生产圣经与连续性资产

“生产圣经”是剧本与 H3 提示词之间的结构化事实层，不等同于普通素材备注：

| 对象 | 维护内容 | 生效范围 |
|---|---|---|
| 角色 | 标准身份、可观察特征、负面约束、跨镜规则、真实身份参考 | 逐镜绑定 |
| 场景 | 空间结构、材质、灯光、天气和允许变化 | 逐镜绑定 |
| 道具 | 外形、材质、状态变化和持有关系 | 逐镜绑定 |
| 视听风格 | 摄影、光色、质感、镜头运动和全片负面约束 | 可应用全片 |
| 声音 | 角色音色、语速、环境声和声音禁区 | 可全片或逐镜 |

每次创建、编辑、素材绑定、镜头绑定、锁定和归档都会增加修订号并保存不可变快照。写操作携带 `base_revision`；旧页面或并发写入不会静默覆盖新版本。只有当前项目的真实受管素材能进入条目，演示图与跨项目素材都会失败关闭。

## P12 可审阅的 H3 生成计划

“生成计划”把创作数据变成真正提交给 H3 的版本化输入，同时保留创作层与执行层的边界：

```text
原始镜头提示词 ─┐
锁定生产圣经 ───┼─> 编译预览 ─> H3 dry-run ─> 人工批准 ─> 后续生产任务
真实受管素材 ───┘       │                               │
                       └─ 不覆盖原文           SHA-256 不可变快照
```

| 门禁 | 行为 |
|---|---|
| 圣经状态 | 只编译已锁定且作用于当前镜头的条目；草稿仅提示，不进入 H3 |
| 引用顺序 | 镜头手工引用与圣经素材去重后，按真实图/视频/音频次序重新生成动态标签 |
| 标签安全 | 圣经片段里的手写 `<Picture n>` / `<Video n>` / `<Audio n>` 被移除并警告，避免错绑 |
| 规格检查 | 校验 32 倍数、1344×768 上限、参考数量、受管文件与 2–15 秒参考视频 |
| 计划失效 | 镜头、对白、规格、圣经修订、素材顺序或校验和变化后，旧批准不再匹配当前哈希 |
| 生产接入 | 当前哈希已批准时，原有单镜生成接口自动使用这份编译快照；未批准时保持旧路径兼容 |

正式验收结果：

| 项目 | 镜头 | 路线 | 规格 | dry-run | GPU | 状态 |
|---|---:|---|---|---|---|---|
| 电梯十三层 | 3 | FL2VA | 608×352、158 帧、6.583 秒 | 3/3 通过 | 未提交 | 3/3 已批准 |

这三个镜头的角色条目目前只有文本，没有真实身份图，因此编译器明确提示人物跨镜漂移风险；这不是流程错误，也不应被描述为已经解决了一致性问题。《雨夜来电》的真实角色身份素材可进入 Ref2VA 编译路径。

## P13–P14 可恢复的整集生产调度

分镜页的批量入口不再连续发送一组临时 HTTP 请求，而是创建持久化生产批次：

```text
选择镜头
   ↓
核对当前批准计划哈希（不占 GPU）
   ↓ 二次确认
冻结逐镜计划快照 → SQLite 生产批次
                         ↓ 单 GPU、逐镜
                    提交 H3 / ComfyUI
                         ↓
              状态轮询 → 待审片 / 失败重试
```

| 场景 | 调度器行为 |
|---|---|
| 正常生产 | 严格按分镜顺序提交；前一镜头完成后才提交下一镜头，避免本机 GPU 队列失控 |
| 页面关闭 | 批次、镜头快照、prompt_id 和事件均在 SQLite 中，浏览器不是任务所有者 |
| API 重启 | 已提交任务继续从 H3 manifest / ComfyUI 同步；尚未提交镜头恢复排队 |
| 提交瞬间中断 | 结果无法确认的项目标记失败并暂停批次，不自动重复提交或重复消耗算力 |
| 暂停 | 只停止后续镜头提交；当前 ComfyUI 任务继续跟踪 |
| 停止 | 未提交镜头标记取消；当前任务不伪装为已经被 ComfyUI 中止 |
| 失败重试 | 最多 1–5 次，且必须仍与原批准计划哈希一致；内容变化后应新建批次 |
| 状态操作 | “项目队列”展示批次进度、逐镜尝试、冻结哈希、恢复事件和底层 H3 任务日志 |

正式验收没有点击最终“确认占用 GPU”：在《电梯十三层》完成 3/3 批量门禁检查并打开二次确认弹窗后选择暂不提交，因此生产批次数仍为 0，未产生本轮 GPU 费用。调度状态机通过隔离数据库验证了串行、暂停/继续/停止、重启恢复、计划漂移与重试上限。

## P15 结构化审片与媒体 QC

审片结论不再只是一段自由备注。每个真实 H3 候选都有独立、可追加修订的质量记录：

| 证据 | 记录内容 | 门禁 |
|---|---|---|
| 完整观看 | 当前候选累计观看秒数 | 标记“通过”前至少覆盖媒体时长的约 80% |
| 五维评分 | 剧情符合、跨镜连续、动作表演、画面质量、声音质量，均为 1–5 分 | 任一维度低于 3 分不能通过 |
| 问题标签 | 人物/服装/场景漂移、动作/运镜、画面瑕疵、伪文字、对白、声音、节奏等 | “保留修改”或“拒绝”必须附可执行说明 |
| 媒体 QC | ffprobe 读取时长、尺寸、帧率、视频/音频编码、声道和采样率 | 无视频流、无音轨或无效时长不能通过 |
| 来源快照 | output_file、prompt_id、文件大小与修改时间 | 文件或生成来源变化后旧结论自动失效 |
| 选择草稿 | 最新结论必须为“通过”，且媒体 QC 与来源快照有效 | 未通过的其他候选返回 409，不改变当前选择 |

《雨夜来电》镜头 03 的既有真实候选完成了只读验收：当前所选 B 仍保持不变；尝试把未审片的 A 切为草稿母版被 409 门禁拒绝。对 B 的实际 ffprobe 结果为 608×352、5.875 秒、H.264、24 fps，AAC 双声道、32 kHz。历史上已经选定的版本不会被迁移脚本伪造成“结构化审片通过”；它们在新面板中明确显示为待补审。

## P16 声音与对白门禁

声音质量分为机器可验证和必须人工判断的两层，平台不会把两者混为一谈：

| 层 | 可确认内容 | 不能据此声称 |
|---|---|---|
| ffprobe / FFmpeg | 音轨存在、编码、声道、采样率、平均/峰值音量、长静音占比 | 对白文字正确、语气正确、口型同步、环境声符合剧情 |
| 人工审片 | 对白内容、口型/时序、环境声连续性，并结合声音质量 1–5 分 | 音频文件底层编码一定无损或满足所有发行平台标准 |

通过候选时：有对白的镜头必须把“对白内容”“口型/时序”“环境声连续性”全部标记为通过；无对白镜头可将前两项设为不适用，但仍要确认环境声。技术 QC 会拦截无可测量信号或几乎全程静音的音轨；响度偏低等问题会作为证据保留，最终导出仍通过现有 loudnorm 做基础响度统一。

《雨夜来电》镜头 03 候选 B 的只读声音分析：平均音量约 -36.0 dB、峰值约 -20.7 dB、按 -45 dB / 0.5 秒阈值检测的长静音占比 0%。这证明音轨有稳定信号，不证明对白内容或口型正确；本轮没有替创作者写入人工声音结论。

## P17–P18 版本化装配与可复现导出

“成片交付”不再直接按照可能变化的分镜表临时拼接，而是先生成一份独立的交付装配计划：

```text
人工已选镜头来源
       ↓
调整顺序 / 字幕开关 / 字幕入点
       ↓
保存草稿修订 → 锁定交付计划（SHA-256）
                         ↓
导出预检复核镜头覆盖与真实媒体
                         ↓
冻结装配哈希 + 来源快照 → 可恢复 FFmpeg 横屏导出
```

| 能力 | 当前行为 |
|---|---|
| 排序 | 装配清单必须完整且只出现一次；顺序独立于创作层分镜排序 |
| 字幕 | 每镜可关闭字幕或设置入点；入点必须落在该镜头时长内 |
| 转场 | 当前仅允许硬切，避免界面承诺尚未实现的复杂转场 |
| 修订 | 保存、锁定、重新开启都会形成不可变版本；过期页面通过 `base_revision` 返回 409 |
| 锁定 | 锁定后字段与排序只读；修改必须显式“开启新修订” |
| 导出门禁 | 未锁定、镜头覆盖漂移、未选真实版本、文件缺失、无视频或无音轨都会失败关闭 |
| 复现证据 | 导出任务快照升级为 schema v2，记录装配修订、计划哈希与逐镜真实来源 |

正式数据验收：

| 项目 | 装配状态 | 导出预检 | 本轮 GPU / FFmpeg |
|---|---|---|---|
| 电梯十三层 | 已锁定 R7，3 镜头、18 秒 | 装配门禁通过；3 镜头仍缺真实已选视频，因此保持阻断 | 未调用 |
| 雨夜来电 | 已锁定 R5，7 镜头、36.877 秒 | 7/7 真实来源、0 条问题、可导出，预检哈希与锁定哈希一致 | 未重新导出；复用既有真实成片作正向验证 |

本轮没有为了“看起来完成”而提交一次重复 FFmpeg 任务；已经完成的《雨夜来电》成片仍可播放和下载，新增验收验证的是装配版本进入导出门禁与冻结快照的生产边界。

## P19 项目归档与完整性备份

项目面板的操作菜单现在提供两层不同能力：

| 操作 | 作用 | 不会做什么 |
|---|---|---|
| 创建并下载归档包 | 冻结项目相关数据、已选镜头、受管素材、当前成片、字幕和生产清单 | 不归档项目，不包含 H3 / ComfyUI 模型权重 |
| 归档项目 | 先创建归档包，再把非当前项目移入“已归档”状态 | 不删除数据库记录或本地媒体 |

| 校验归档 | 复核 ZIP、项目数据和每个媒体文件的 SHA-256 | 不把“文件没损坏”误称为内容质量通过 |

归档数据覆盖剧本、章节、Agent 运行记录、分镜同步、生产圣经、H3 计划、生产批次、候选、审片、装配计划、导出任务与事件。媒体只收录受管素材、已选候选/成片和当前交付文件；外部未选候选不会被复制，避免归档包无边界膨胀。

|---|---|
| R1 | 完整性校验通过，但演练发现当前导出的 5 个相对路径未被收录；此版本不作为生产验收依据 |
| R2 | 19.87 MB，156 条项目记录，28 个媒体/交付文件，遗漏 0；ZIP、数据和逐媒体 SHA-256 全部通过 |

R2 SHA-256：`fbf6c7696dc33f9d7187c26208f010d033727044dcb11e95c5002e5ff004df85`。演练执行了“归档 → 禁止直接激活 → 恢复到工作台”，项目数据与既有归档版本均保留。当前实现支持同一工作区内恢复；尚未实现把 `.jingchang.zip` 导入一台全新机器，因此不能把 R2 描述为已经验证的跨机迁移。

|---|---|---|
| 创作简报 | 编辑主题、类型、基调、受众、目标时长、约束，批准/退回草稿 | 每次保存生成只读修订 |
| 剧情提案 | 新建、编辑、归档、定案 | 数据库唯一索引保证同一项目只有一个定案；切换定案保留双方修订 |
| 角色卡 | 新建、编辑、批准、归档 | 记录身份、目标、阻碍、性格、关系、视觉/声音连续性和参考说明 |
| 章节与小节 | 新建、编辑、批准、归档、上下排序、拆分、合并 | 稳定 ID；刷新、重启和项目切换后顺序不变；乐观锁拦截过期编辑 |
| 版本历史 | 在所有层级查看修订号、时间、来源和只读快照 | `creative_revisions` 只追加，不覆盖历史内容 |

新建项目现在允许不录入初始镜头，并直接进入“创作规划”。旧项目首次打开时会从已有项目、剧本或分镜建立一份可编辑的规划底稿；迁移幂等且不会修改既有镜头、候选、生成任务、验收或归档记录。项目归档包同时包含简报、提案、角色、章节、小节与全部创作修订。

## 分层创作本地 Agent（Issue #3）

“系统设置 → 本地 Agent”分别维护 Codex CLI 与 Kimi Code CLI 的可执行文件、模型和超时配置。探测会分开显示 CLI 安装、认证配置、模型配置和实际可调用性：Codex 使用 `login status`，Kimi 会严格解析 `provider list --json`，验证 provider/model 记录类型和引用关系，并只接受结构化字段中的精确模型别名/ID；空模型配置需要可解析的默认模型，否则会诚实标记为“未验证”。两者都不发送生成请求或消耗模型额度。配置不包含 API Key、Token 或其他明文密钥。

| 创作层级 | 结构化输出 | 人工确认后的写入 |
|---|---|---|
| 剧情 | 标题、梗概、核心冲突、结局 | 新建剧情提案，或为目标提案创建新修订 |
| 大纲 | 章节及其小节数组 | 原结构进入可追溯归档，新结构创建正式修订 |
| 章节 | 标题、摘要、节奏、时长、小节 | 新建章节，或替换目标章节内容与小节 |
| 小节 | 标题、摘要、正文、节奏、时长 | 新建小节，或更新目标小节修订 |
| 正文 | 小节正文 | 只更新目标小节正文并创建新修订 |

所有层级都支持生成、扩写、压缩、重写和校对。调用先持久化输入哈希、目标修订，以及冻结的可执行文件规范路径、文件内容 SHA-256、适配器、模型、版本和超时；提供方后来改配置或替换同名程序不会改变已经排队的运行，启动前也会复验内容指纹。解析失败、超时或取消不会修改正式内容。成功输出先进入差异审阅，只有人工确认才写入，且确认时会再次检查目标修订以避免覆盖更新。失败或取消任务可使用同一提供方重试，服务重启中断的任务会被标记为可恢复；系统不会静默切换提供方。人工编辑始终独立可用。

创作规划首屏只等待人工工作区数据；缓存的 Agent 状态使用 `probe=false` 独立加载，主动探测在后台运行并有超时取消。即使 CLI 探测挂起或失败，简报、提案、角色、章节和小节的人工编辑仍会立即可达。

Kimi 的完整提示词只通过 ACP 标准输入发送，不进入进程参数或持久化命令记录。每次调用都使用临时空技能目录和 `tools: []` / `subagents: []` 的受控 Agent 配置，声明空 MCP、禁用客户端文件和终端能力，并仅向子进程传递白名单环境变量；如果 ACP 仍报告工具调用或权限请求，适配器会取消并拒绝整条提案。Codex 也通过标准输入接收提示词，并保持只读沙箱。

排序、拆分和合并会在单个写事务开始时核验全部受影响内容及父章节的修订号；任何陈旧标签页都会收到 409，并且不会产生部分排序、内容覆盖或修订记录。“归档内容”视图保留提案、角色、章节和小节的类型、标题、归档时间、操作来源与版本历史入口。

本阶段允许显式调用已配置的 Codex/Kimi 生成待审提案，但不会自动同步分镜，也不会提交 GPU；这些生产步骤由后续 Issue 单独实现。

## 结构化小节到分镜的安全同步（Issue #4）

“创作规划”中的小节现在是生产分镜的正式叙事来源。每个小节分别维护场景、动作、对白、声音、视觉意图和预计时长；人工批准或退回都会创建不可变修订。只有全部活动小节获批后，才可以进入同步门禁：

```text
结构化小节草稿 → 人工批准 → 无副作用差异预览 → 明确确认 → 稳定分镜映射
                              ├─ 新增 / 修改 / 删除 / 重排
                              └─ 标题 / 画面 / 对白 / 声音 / 时长逐字段对比
```

| 规则 | 当前行为 |
|---|---|
| 稳定来源 | 同一小节持续映射同一分镜 ID；项目切换不会串数据，历史手工分镜不会被伪造来源 |
| 同步安全 | 预览不写数据库；确认时复核计划哈希；相同计划重复提交不会创建重复分镜 |
| 删除保护 | 目标分镜已有候选、定稿、交付或生产任务证据时，整次删除同步被阻断并说明原因 |
| 连续性规则 | 已批准角色卡的外观与声音规则自动成为锁定生产圣经条目，并显示角色卡及修订来源 |
| H3 过期机制 | 已批准的小节、角色卡或镜头引用发生变化时，相关 H3 计划立即标记过期并记录原因 |
| 历史兼容 | 旧项目可继续使用原手工分镜；首次打开只建立规划底稿，不倒填虚假的小节映射 |

同步成功后页面会重新读取项目，再进入“分镜与生成”，因此新分镜、声音提示和小节修订来源会立即可见。此门禁只维护内容与可追溯计划，不执行 H3 dry-run、不提交 GPU，也不触发审片或导出。

## 低清候选、结构化审片与母版装配（Issue #5）

生产路径现在把“批准计划”到“锁定装配草案”连成一条可恢复、可审计的工作流：

```text
小节/分镜已批准
   ↓
章节、整个项目或手工选择镜头
   ↓ 应用 608×352 / 768×448、时长、每镜 2–4 候选
H3 dry-run + 人工批准当前计划哈希
   ↓ 明确确认占用 GPU
单 GPU 可恢复生产批次
   ↓ 每次 attempt 冻结 prompt / seed / spec / plan hash / Comfy 任务 / 媒体证据
至少 2 条真实候选 → 同屏/依次对比 → 结构化评分与备注
   ↓
append-only 草稿母版版本（可回滚，不覆盖候选）
   ↓
排序 + 入出点 + 字幕 + 原声/静音 → 锁定装配草案
```

| 生产环节 | 门禁与可追溯行为 |
|---|---|
| 批次选择 | 后端无副作用 preflight 逐镜冻结批准计划、H3 adapter 输入哈希和对应 validation job；每镜至少 2 条候选，最长边不得超过 768。创建请求必须携带 preflight hash 与幂等键，事务内复核后才排队 |
| 调度恢复 | `production_shot_leases` 保证同一镜头不能跨批次并行提交；attempt 绑定精确 draft job/revision/candidate set。外部同步或人工对账推进 job revision 后，调度器只在集合仍属于原 attempt 时用 CAS 消费；人工对账请求必须携带明确 `job_id + expected_revision`，并在当前项目/镜头内原子核验，绝不按“最新任务”猜测目标。任何非权威结果、所有权或 CAS 冲突都会把 lease 置为 unknown，并在同一事务创建项目级可审计冲突，不会留下没有处理入口的未知占用 |
| 冲突审计 | “项目队列”按当前项目展示升级重复 attempt 及运行期 poll 冲突。升级冲突要求每个条目的 `1..attempts` 都有独立、唯一 draft job 与各自零提交证明；运行期冲突冻结精确 attempt/job/revision，只有该 job 经人工确认或受信任 pre-spawn 证据证明零候选、零媒体提交后才能解除门禁并重试。解决记录保存人员、时间、说明和 revision CAS |
| 候选证据 | 保存 H3 项目、prompt/candidate ID、实际 prompt、seed、规格、plan hash、输出路径、文件大小和媒体状态；旧候选缺失真实文件或任务证据会显示为“历史证据债务” |
| 结构化审片 | `verified` 必须同时匹配唯一 production attempt、精确 draft job、plan/input hash、prompt、candidate ID、seed、规格和受管媒体 SHA-256；缺任一项都显示为历史债务且不计入“至少 2 条” |
| 草稿母版 | `base_revision` 必填；同一写事务复核最新审片原始快照及媒体 path/size/mtime/SHA 后只追加选择/回滚修订，回滚不会删除或覆盖候选 |
| 装配草案 | 每项规范化冻结 section revision、镜头正文/对白/字幕、candidate、master/review revision 和媒体路径/SHA，以及顺序、入点、出点和原声/静音策略；锁定事务逐项复核，旧计划缺凭证时失败关闭 |
| 可复现导出 | 导出只使用锁定装配里的候选与校验和，不跟随后来变化的“当前选择”；认领后把每个来源复制成 run 私有、只读、内容寻址的 staging，复制前后验证 original/staged SHA，FFmpeg 真正应用 `trim/atrim`、静音和冻结字幕且只读取 staged 路径。最终发布从最后 SHA 校验到 manifest/current CAS 全程持有 Windows 禁写/禁删共享句柄；锁失败或 staged 副本被改即零发布，原文件在复制成功后变化不影响本次确定性输出 |
| 项目归档 | 归档包包含生产批次、逐次 attempt、审片修订、母版历史和全部装配版本，原始候选媒体继续按既有受管媒体规则校验 |

本阶段不执行高分辨率精修，也不会把普通放大称为高清重生成。自动化测试通过受控 fake 适配器验证提交、恢复和证据合同，不调用真实 GPU 或本地 Agent 额度。

## 逐镜高清策略与横屏交付（Issue #6）

“高清交付”页把已锁定的低清母版推进为独立、可审阅的高清版本。只有存在 append-only 低清母版的镜头才能创建策略；草稿候选、历史证据债务或后来发生变化的来源都会失败关闭。

| 高清策略 | 实际操作 | 证据与风险 |
|---|---|---|
| Ref2VA 高清精修 | 把低清母版作为视频参考，在目标分辨率重新生成 | 属于模型重生成；记录 prompt、seed、参考、模型、workflow、Comfy task 和媒体 SHA；必须人工确认身份、动作与运镜漂移 |
| 原策略高清重生成 | 沿用低清母版的 FL2VA / Ref2VA 路线、prompt、seed 与参考重新采样 | 属于模型重生成；同样可能漂移，不能承诺复现原镜头 |
| 确定性保真放大 | FFmpeg Lanczos 等比缩放并补边到目标画布，保留原时长和音轨 | 属于像素缩放，不调用 GPU，不会创造新细节，也不会伪称模型高清重生成 |

每次策略保存都会创建新修订。`dry-run` 只冻结命令、模型/workflow、源媒体和计划哈希；模型策略必须在界面二次确认后才可进入 GPU 队列。dry-run、实际任务与归档分别持有持久 lease，归档冻结期间不会再认领高清、低清生成或导出任务。实际执行会先把低清母版和参考素材稳定复制到本次 attempt 私有 staging，再在 runner 前用短事务复核计划、母版、路径、大小与 SHA。任务采用逐镜 lease、幂等键和可恢复状态：确认未启动的失败可以安全重试，外部进程启动后结果未知则保持人工对账门禁。完成产物经过私有输出、内容寻址发布与 Windows 禁写/禁删句柄保护后，才与 job/artifact 在同一事务完成；记录输入/输出 SHA-256、真实规格、音轨、prompt/task ID、实际 seed/参考和完整 provenance。高清审片保存五维评分、观看时长、备注和漂移确认；定稿与回滚只追加 `hd_master_versions`，不覆盖历史产物。

```text
低清母版
  → 选择三类高清策略之一
  → dry-run（零 GPU）
  → 模型策略人工确认 / 确定性缩放直接执行
  → 高清与低清并排审片
  → append-only 高清定稿
  → 锁定装配（顺序、入出点、字幕、原声/静音）
  → 1344×768 或更高横屏 FFmpeg 导出
  → 画面与声音分别签署
  → 冻结验收 JSON/SHA
  → 创建并校验完整项目归档
```

交付装配只引用锁定时的高清 artifact、高清母版修订和媒体 SHA。导出仍使用每次 run 私有的内容寻址 staging；单镜头和多镜头的 `.sources.json` 都固定为 JSON 数组。当前成片必须至少为 1344×768 横屏、可解码、镜头覆盖完整且包含音轨，画面连续性与声音签署必须绑定精确 `export_run_id + video SHA-256`；切换或重新导出后旧签署不会授权新成片。项目归档包含全部高清计划、验证、任务、产物、审片、定稿历史和经 SHA 校验的高清媒体；归档媒体也先进入私有 staging，并对 ZIP 目录、项目数据和每个媒体的大小/SHA 做完整复验。任何媒体缺失、被替换或复制期间变化都会让本次归档失败关闭，既不发布不完整 ZIP，也不把项目标记为已归档。

### 本地配置与能力边界

| 依赖 | 配置/用途 | 边界 |
|---|---|---|
| ComfyUI | `COMFYUI_URL`，默认 `http://127.0.0.1:8188` | 仅模型重生成策略需要；平台不会把 dry-run 说成已生成 |
| H3 工作流 | `H3_PIPELINE_SCRIPT`，默认查找本仓库或用户技能目录里的 `h3_video_pipeline.py` | Ref2VA / FL2VA 的真实能力取决于本地模型、节点和显存；不保证固定耗时或绝对连续性 |
| ComfyUI 输出 | `COMFYUI_ROOT` 下的 `output` | 低清母版与高清产物必须在受管输出根内并通过 SHA 校验 |
| FFmpeg / ffprobe | `PATH` 中可调用 | 用于确定性放大、媒体 QC、音轨/字幕装配和横屏导出；缩放不增加生成细节 |
| 桌面/API | `scripts/start.ps1` 或 Release 客户端启动本地服务 | 当前是本机单用户工作区，不是云端多人协作或发布平台 |

自动化端到端验收从空项目开始，覆盖简报、多个剧情提案及单一定案、角色、章节/结构化小节、批准同步、双候选审片、低清母版、高清策略、装配、真实小媒体 FFmpeg 导出、双签、验收与归档。测试里的 Agent/H3/Comfy 候选明确记录为 `controlled-fake-h3-no-gpu` 和 `real_model_output: false`，不调用真实 Agent 额度、ComfyUI 或 GPU，也不冒充模型生成；确定性放大与最终装配则实际执行本机 FFmpeg。

```powershell
python -m unittest backend.test_end_to_end_delivery -v
python -m unittest backend.test_hd_ffmpeg -v
```
